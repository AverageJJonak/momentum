**The contract (§1 of the guide):** metres, Unity axes (the scripts swap y/z both ways), 60 fps on scaled time; bone names exactly the rig's (arms: HandR/HandL are the wrists he animates, ShoulderR/L and ElbowR/L are IK-driven reference, fingers F00..F32 + T0/T1 fold about local X, Fist/Grip sockets; enemies: Torso/HeadPivot/ArmL/ArmR/LegL/LegR + each kind's sub-pivots, root at the feet facing +Z, never keyed); the hand frame +Z fingers / +Y back of hand / thumb inner; the camera is the first-person root with no translation keys; clip names `<weapon>_<action>[_n]` and `<enemykind>_<action>[_n]` (the code-name ↔ staff-name table is in the guide); loop flag; EVENTS = pose markers (hit, step, shell, sound) raised as C# events; the HIT-FRAME table at 60 fps (jab/cross extension frame 4, cane strike frame 11, maul windup to frame 12 then the land, blunderbuss frame 0, deck flick frame 3, kick frame 5, the parry guard up by frame 9); reach (shoulders ±0.27,−0.30,−0.12, arm 0.61 m, wrists ≤ 0.6 m from the camera at rest); the fist-wrist rule.

**Rig export:** Unity menu `Momentum/Animation/Export Rig Proxies` (Editor/RigExporter.cs + RigExportWalk.cs): in edit mode builds the arm rig and one enemy of every kind (23 rigs) in a temporary scene, walks each hierarchy (bones = transforms without renderers; proxies = primitives with type/pose/size/colour; hitboxes/text/lines/lights skipped; repeated names become dotted paths), writes `Tools/Animation/rig_arms.json` and `rig_<kind>.json`, destroys everything. JSON only (no FBX package added). Run it once in the editor and send the folder.

**Blender (Tools/Blender):** `momentum_rig_import.py` (RIG_JSON at the top or a file dialog or `blender --python … -- rig_arms.json`): empties with the bone names, proxies as unselectable coloured meshes, 60 fps/metres, a FirstPersonCamera at 58° vertical for the arms, scene props momentum_clip/momentum_loop/momentum_out. `momentum_clip_export.py` (Run Script with the rig selected, or headless with `--name --out [--loop]`): bakes the frame range from evaluated matrices, writes moving bones (wrists always) in Unity axes, finger curls per hand (0..1), markers → events. Desk-checked only (no Blender here): eyeball the axis conversion on the first real clip.

**Runtime (Assets/Scripts/Clips):** `ClipLibrary` (loads Resources/Clips/*.json once; Has/Get/Names/Count/Reload; flat arrays, no per-frame allocation). `ArmClipDriver` (on the rig's camera; `static Play(name, speed=1, bool? loop=null, Transform weapon=null, ArmRig.HandSide? weaponHand=null, Action<string> onMarker=null)`, `Stop()`, `Playing/Current/Progress`, `static event Marker`): each keyed hand is held on a driver-owned anchor via HoldWeapon every LateUpdate before the rig solves (a Hold outranks the weapon's Drive that frame; alternating anchor pairs so clip→clip springs; the weapon's own calls resume the instant the clip ends); fingers → the nearest curl state; `ArmClipCarry` carries a passed weapon in the hand. `EnemyClipDriver` (`static Play(Enemy, name, speed, loop, onMarker)`, `Stop(Enemy)`, `Apply()`): writes keyed pivots' localRotation (and position when keyed) over the procedural pose with 0.1 s blends; bosses unsupported. The ONE hook: Enemy.cs `public EnemyClipDriver clips;` + `clips?.Apply();` right after the Animate* switch. Opt-in only: a weapon file calls `if (ClipLibrary.Has("cane_slash_1")) ArmClipDriver.Play("cane_slash_1", 1f, false, sword);` where it would run its procedural beat; no weapon or enemy file plays anything yet. Example clip: `Resources/Clips/example_idle.json` (a 2 s breathing loop of the right fist at the knuckles' stance).
